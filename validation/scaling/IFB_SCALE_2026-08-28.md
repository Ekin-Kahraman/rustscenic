# IFB production-scale validation

Date: 2026-08-28. All accepted runs used RustScenic 0.5.0 from clean commit
`f8f605cc2ae3d942ecf33d76872e5a6e4110bfbc` on one IFB Slurm node. Rayon
was bounded by the allocated CPU count and OpenMP, OpenBLAS, MKL, BLIS and
NumExpr were fixed to one thread. The JSON artefacts are external to Git,
declare `path_policy="portable"` and contain no absolute paths.

These are execution-scale and numerical-invariant checks. Synthetic runs do
not establish biological validity, and single observations on shared nodes are
not general speedup claims.

## 1.2-million-cell production-parameter GRN curve

Slurm job `1484089` used 16 CPUs on `cpu-node-1` (Xeon E5-2695 family), a
5,000-estimator ceiling, `early_stop_mode="arboreto"`, window 25, subsample
0.9, 300 genes and 30 TFs. Every point ran in a fresh process from a nested
row-prefix input; the harness SHA-256 was
`885b4b6cc1129635f747013358ec9a8904ebd545036d8a782b1bbda9fa411880`.

| Cells | Wall s | Peak RSS MB | Edges | Fitted trees mean / median / max |
| ---: | ---: | ---: | ---: | ---: |
| 50,000 | 5.043 | 252.8 | 8,859 | 29.443 / 26 / 80 |
| 100,000 | 6.247 | 424.2 | 8,843 | 32.090 / 26 / 110 |
| 200,000 | 13.657 | 767.6 | 8,845 | 37.107 / 26 / 131 |
| 400,000 | 39.079 | 1,454.3 | 8,876 | 42.770 / 26 / 178 |
| 800,000 | 89.314 | 2,827.7 | 8,840 | 47.477 / 27 / 198 |
| 1,200,000 | 149.393 | 4,201.0 | 8,855 | 50.857 / 27 / 224 |

The wall-time log-log slope was 1.134, below the repository's 1.30 regression
threshold. Segment slopes were 0.309, 1.128, 1.517, 1.192 and 1.269; the
200k-to-400k segment is therefore locally super-linear even though the whole
curve is near-linear. Peak-RSS slope was 0.891. The 24-fold cell increase used
29.624-fold wall time and 16.618-fold peak RSS. Mean fitted trees rose with
cell count, so part of the wall increase is scientifically required adaptive
work rather than a fixed-work kernel effect.

Every output was non-empty, every importance was finite and every point
reported the Rust backend. Each point records a distinct canonical output
SHA-256. The portable artefact SHA-256 is
`e171ee8808e4101448edb93906fefa0d27d8eca1883b52829d7d094d473da6ee`.
Slurm completed the six-point job in 5:51 with sampled batch MaxRSS 2,837,308
KiB.

The full curve was repeated as job `1499464` on a different CPU generation
(EPYC 9754). It passed an explicit `--max-slope 1.30` gate with slope 0.751,
and all six canonical output hashes and all fitted-tree telemetry matched the
Xeon run exactly. The repeat artefact was portable and passed an independent
post-run assertion; its SHA-256 is
`fe967f99ad5c1809047862fcfc175031d8f7e26e53ca13e1948ccb299010cde4`.
Slurm labels the wrapper `FAILED` because a shell-quoted one-line assertion
after the artefact write was parsed as invalid Python. The measured program
completed, wrote the valid artefact and passed the corrected independent
assertion, so the wrapper error is classified as orchestration-only rather
than hidden as a successful job.

## Real PBMC3k production GRN

Slurm job `1484082` used the 10x PBMC3k filtered-feature H5, 2,767 QC cells,
21,335 genes, 1,420 TFs, the 5,000-estimator ceiling and corrected arboreto
stopping. The benchmark validator returned `status="ok"` with no failures.

| Threads | GRN wall s | Speedup | Efficiency | Peak RSS GB | Edges |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 1,944.918 | 1.000 | 1.000 | 0.722 | 1,798,777 |
| 4 | 515.931 | 3.770 | 0.942 | 0.764 | 1,798,777 |
| 8 | 271.125 | 7.174 | 0.897 | 0.771 | 1,798,777 |
| 16 | 137.658 | 14.129 | 0.883 | 0.776 | 1,798,777 |

All thread counts produced the same edge count and fitted-tree distribution:
minimum 25, median 26, mean 26.6708 and maximum 150 over 21,335 targets. This
shows strong useful scaling through 16 cores without nested BLAS/OpenMP pools.

The cell-subset curve is intentionally not interpreted as a linearity result.
At 500, 1,000 and 2,000 cells, some underdetermined targets hit the 5,000-tree
ceiling; mean fitted trees were 523.46, 192.06 and 37.66. At all 2,767 cells no
target hit the ceiling and the mean was 26.67. The resulting wall time falls
as cells are added, because early-stop work changes much more than row count.
This is a real scientific regime effect, not evidence of negative complexity.

The portable artefact SHA-256 is
`8250fc9448578b3ea757f7651ec8965b3e2b6622249ec813932b61e2934ac730`.
Slurm completed the full subset and thread matrix in 1:01:36 with sampled
batch MaxRSS 871,008 KiB.

## Controlled seven-stage 100k-to-200k comparison

Jobs `1483924` and `1484141` used the same `cpu-node-3` Xeon E5-2695-family
node, seed 42, 15,000 genes, 50,000 peaks, 30 planted programmes, Gibbs topics
with 100 sweeps and eight threads, and a 20-estimator scale-check GRN. The
ATAC non-zero counts were 387,621,954 and 775,248,174, a 2.000011-fold input
increase.

| Stage | 100k s | 200k s | Ratio |
| --- | ---: | ---: | ---: |
| Synthetic construction | 128.4 | 259.4 | 2.020 |
| Topics | 1,116.2 | 2,259.6 | 2.024 |
| GRN | 174.9 | 404.9 | 2.315 |
| Enhancer links | 15.9 | 32.6 | 2.050 |
| AUCell | 5.1 | 10.5 | 2.059 |
| Seven analysis stages | 1,312.8 | 2,708.2 | 2.063 |

In-process peak RSS was 21.21 and 42.31 GB, a 1.995-fold ratio. Slurm's
sampled batch MaxRSS was lower at 13,621,676 and 28,865,368 KiB, so the
in-process high-water mark is retained as the conservative memory figure.
Both runs recovered 30/30 topics, 30 eRegulons and valid AUCell shapes. The
200k output contained 442,017 GRN edges, 900 cisTarget rows, 93,750
peak-to-gene links and 90,720 eRegulon rows. All finite, normalisation,
non-empty and shape checks passed; the largest 200k topic-row errors were
`7.15e-7` for cell-topic and `8.18e-5` for topic-peak.

The layer audit therefore keeps the implementation changes narrow:

| Layer | 100k-to-200k ratio | Decision |
| --- | ---: | --- |
| Input construction | 2.020 | Linear; no production-code change |
| Topics | 2.024 | Linear; compact only the duplicated per-token document index |
| GRN | 2.315 | Preserve adaptive stopping; reduce internal row-index width |
| Enhancer links | 2.050 | Linear; no change |
| AUCell | 2.059 | Linear; no change |
| Total analysis | 2.063 | Linear within measured shared-node noise |

cisTarget, regulon construction and eRegulon assembly were not material
runtime contributors. Moving their orchestration from Python would add code
without addressing the measured bottlenecks.

Artefact SHA-256 values were
`e1570846bc0389cb5904fe1d0e0a3775f1f09069d4a39b287d3410522d85b6f1`
for 100k and
`d7daf712ff0f36e28d6f688baf0995c50ff9b22dedfadf455623f620fd62bcf5`
for 200k. The 200k harness SHA-256 was
`22b3d12b13c5f517bd8f75383184f808967508c85fde4c5c5b5283e7d3f2aecc`.

## Real 10x human-brain ATAC topics

The same 10x GEM-X human-brain inputs audited for issue #94 were filtered to
the matching cell-called barcodes, binarised and kept sparse. The 10,000-cell
matrix had 130,127 peaks and 80,895,740 non-zero values. Input SHA-256 values
were recorded in the artefact.

A 100-sweep, K=30 Gibbs run on all 10,000 cells and 16 threads completed in
462.170 s at 2.558 GB process peak RSS, used 29/30 cell-argmax topics, had no
empty cells and mean NPMI 0.2113. At 5,000 cells, four, eight and sixteen
threads took 462.822, 255.138 and 257.468 s: 8 threads gave 1.814x speedup over
four, while 16 threads gave no further throughput. Four-vs-eight assignment
ARI was 0.4522 and matched top-10-peak overlap was 0.0967. Thread count is
therefore a biological model setting for AD-LDA, not only a compute setting.

An independent eight-thread repeat on another node took 254.210 s and exactly
reproduced assignment SHA-256
`0d218e6f602cfd25b965f258c633dc37279aea645f84b408757fee642681d92e`,
active-topic count 29 and NPMI 0.193001. This is the fixed seed plus fixed
thread-count determinism check. The accepted artefact SHA-256 values were
`2ca16e9cf89214b1b847d247deb3e4b8495dd8b684f0904170044dae3e131037`
and `ca07495af79cd5ce812b2d1afc40cf54439921559ad455dddef7449779f52967`.
The executed script SHA-256 was
`78f5c40866a2cda83d57b9dacc019505c745200e66f2f907a1e4bc07bc74bba7`;
the review-set script differs only by adding its own SHA-256 to future
artefacts.

The online-VB control was rejected as a production result: on 2,500 cells it
took 657.744 s, reached 9.626 GB and assigned cells to only 3/30 topics, with
mean NPMI 0.0719. This failure motivated the explicit collapse warning and
pipeline-manifest topic summary. It was not hidden or used as a favourable
performance number.

### Compact Gibbs token audit

On 2026-08-29, a local Apple M5 audit used the existing real mouse-brain ATAC
matrix (4,770 cells x 172,193 peaks, 45,288,596 non-zeros and 60,014,129
expanded Gibbs tokens; input SHA-256
`e629f2f3738d07e2377910b42274eb6a1d84ddf6476de0b67d84876e61dc86f8`).
Three baseline and three compact runs used K=30, five sweeps, eight threads
and seed 42. Median wall time was 5.062 versus 4.961 seconds and median process
peak RSS was 1,668.2 versus 1,312.0 MB, a 21.4% reduction. All six runs
produced the same cell-topic plus topic-peak SHA-256
`3f2998a4715d956eda6f7d67be1d265edcf5ba674010b31061a75c4a9f3176a0`.
The short run validates representation and memory, not topic convergence.

## Production boundary

The current evidence supports bounded single-host execution, corrected
arboreto stopping, useful GRN scaling through 16 cores, a 1.2-million-cell
fixed-schema GRN, a controlled 200k seven-stage run and real 10k-cell ATAC
topic behaviour. It does not yet prove the complete 1.2-million-cell spatial
dataset: that matrix has not been uploaded to the shared project. Its gene
count, sparsity, annotations, motif-ranking inputs and final-write size are not
represented by the 300-gene curve. The required next gate is a 100k subset of
the actual object, followed by 200k, 400k, 800k and finally 1.2 million only
after measured memory headroom is safe.
